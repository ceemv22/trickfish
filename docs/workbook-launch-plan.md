# Workbook: first self-service sales experiment

Prepared 2026-11-08. Operational draft, not an active store or a revenue forecast.

## Decision

Offer a narrow Windows PGN-to-worksheet utility. No cold email campaign, sales calls, AI-profiler promise or new engine work is required for this attempt. Initial proposed price: USD 9 once. Do not present it as validated willingness to pay. Previous EUR 19/29 ideas concerned different manual-service scopes and are not the price of this download.

Choose Gumroad for the first prepared listing. Its public [pricing page](https://gumroad.com/pricing), checked 2026-11-08, lists no monthly charge, 10% plus USD 0.50 for profile/direct-link transactions and 30% for Discover transactions. Its [fee help page](https://gumroad.com/help/article/66-gumroads-fees) must also be reviewed at onboarding because processing and other deductions may affect the final payout. Do not calculate a guaranteed net payout from the headline rate alone. These costs can change. Merchant-of-record sales-tax handling does not mean all seller income/reporting obligations disappear.

The storefront is a delivery/checkout channel, not a promise that the platform will provide buyers. Eligibility, verification, payout availability and final fees must be checked against the owner's actual account. No account has been inspected or configured in this work.

## Prepared materials

- `workbook-store-listing.md`: paste-ready description, scope and limitations.
- `workbook-customer-start.md`: written first-use instructions.
- Local preview: real exported student/coach PDFs, PGN input and rendered output images.
- Isolated Windows package with corresponding source, notices and tested startup/export.

Use the executable package for the exact accepted build, not a random earlier local ZIP. Keep its archive hash and build receipt. The scope license and source ZIP must accompany the delivered binary. A green build is not a clean-machine certificate.

## Required final owner steps

The account owner must sign in, complete any identity/payout verification and personally accept legally binding platform terms. Never put passwords, bank details or identity documents in the repository/chat. This is an account/contract dependency, not another product-development task. Complete it only on the intended official platform.

Once the owner account is usable, create a product draft using the prepared text and USD 9 price. Upload the binary ZIP to the paid delivery field, and explicitly mark the preview files as free samples if the platform supports that configuration. Add a monitored support address and review the actual customer/refund policy. Before publication, inspect the buyer-facing page and checkout configuration. Test delivery using the platform's supported seller-test mode when available; do not claim a purchase or charge a real card merely to manufacture a first sale.

No checkout URL should be put in public copy until it exists and has been verified. Do not use a fake Buy button, placeholder payment link, customer count or testimonial.

## Demonstration script: about 45 seconds

1. Show the PGN input and say: "I already have chess lines for a lesson."
2. Open the actual application and load the same file.
3. Select two positions; briefly show the board preview and selection count.
4. Export into a new folder.
5. Open the student PDF: board, question, writing space, no source answers.
6. Open the coach PDF: supplied continuation and comment.
7. End with: "Windows preview. Processes files locally. GPL source included. See the sample before buying."

Record a real screen interaction only after it works visibly. Rendered PDF images alone must be labeled as output previews, not passed off as an interactive application recording. No CGI interface, fake wait-time comparison or claimed time savings.

## Public post draft

> I built a small Windows tool for turning supplied chess PGN lines into printable worksheets. Select positions, export a student sheet and a separate key with your original continuations/comments. It runs locally and includes GPL source. It does not generate engine-certified solutions. Here is a free example of the input and both outputs. The prepared Windows download is USD 9.

Publish only after the product and preview links are real. Begin with one relevant public channel or an owned profile. Before using a chess community, read its current self-promotion rules and use the allowed place/format. No mass posting, unsolicited DMs or cold emails. A posting plan is not evidence that any community has approved the promotion.

## Measurement

Record actual events, once per day or when materially changed:

```text
Date:
Public post / source:
Product page visits (if reported):
Preview downloads (if reported):
Completed paid orders:
Refunds:
Actual payout / pending balance:
Support problems:
Feature requests in buyers' own words:
Next single action:
```

Unknown metrics stay unknown, not zero. A private preview, internal download, test checkout or positive comment is not a paid order. A paid order is not necessarily settled payout.

If nobody reaches the page, address discoverability and presentation before adding features. If people reach it but cannot understand the output, improve the demonstration. If interested people hit an actual import/export failure, fix that defect. If a usable demo attracts no purchase interest, revisit value/price/target audience; do not assume another large commit will fix demand. Agree on the next experiment from observed data, without a promised date for the first dollar.
